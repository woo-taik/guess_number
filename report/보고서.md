# 1. 과제 개요

## 1.1 과제 요구사항

컴퓨터가 1~100 사이의 난수를 생성하고, 사용자가 그 숫자를 맞추는 게임을 작성한다.

| 번호 | 요구사항 | 구현 위치 |
|------|----------|-----------|
| ① | 1~100 사이의 난수 생성 | `play_round()` — `rand()` |
| ② | 입력할 때마다 크거나 작음을 알려줌 | `play_round()` — `if-else` |
| ③ | 숫자를 맞추면 한 판 종료 | `play_round()` — `break` |
| ④ | 어떤 숫자를, 어떤 과정으로, 몇 번 만에 맞췄는지 출력 | `print_result()` — 배열 `history[]` |
| ⑤ | 게임을 계속할지 묻고 진행 여부 결정 | `ask_yes_no()` + `main()`의 무한 루프 |

## 1.2 프로그램 한눈에 보기

프로그램은 다음 순서로 동작한다.

```
프로그램 시작
 └─ [바깥 루프] 한 판
     ├─ ① 난이도 선택 → 허용 시도 횟수 결정
     ├─ ② 정답 난수 생성 (1~100)
     ├─ [안쪽 루프] 남은 기회가 있는 동안
     │    ├─ 숫자 입력 (유효성 검사)
     │    ├─ 입력한 숫자를 history[] 배열에 기록
     │    ├─ 입력 < 정답 → "더 큽니다!"
     │    ├─ 입력 > 정답 → "더 작습니다!"
     │    └─ 일치        → 승리, 안쪽 루프 탈출
     ├─ ③ 결과 출력 (정답 / 시도 횟수 / 시도 과정 전체)
     └─ ④ "새 게임을 시작하시겠습니까? (y/n)"
          → y면 바깥 루프 반복, n이면 종료
```

# 2. 가정 및 설계 방침

과제 명세에 명시되지 않은 부분은 다음과 같이 스스로 가정하여 구현하였다.

## 2.1 난이도 (시도 횟수 제한)

명세에는 시도 횟수 제한이 없으나, 제한이 없으면 사용자가 1부터 100까지 순서대로 입력해도 반드시 성공하므로 게임의 긴장감이 없다. 따라서 **게임 시작 시 난이도를 선택**하고, 난이도에 따라 주어지는 시도 횟수를 다르게 하였다.

| 난이도 | 시도 횟수 | 근거 |
|--------|-----------|------|
| 쉬움 | 15번 | 충분한 여유 |
| 보통 | 10번 | 이분 탐색(최대 7번)이면 확실히 성공 |
| 어려움 | 5번 | 이분 탐색으로도 부족할 수 있어 운이 필요 |

1~100 사이의 숫자는 **이분 탐색(binary search)**으로 최대 7번이면 반드시 찾을 수 있다. 매번 범위를 절반으로 줄이므로 $\log_2 100 \approx 6.64$, 즉 7번이다. 이 값을 기준으로 난이도를 정하였다.

## 2.2 잘못된 입력의 처리

사용자가 숫자가 아닌 값(`abc`), 범위를 벗어난 값(`0`, `101`), 빈 줄 등을 입력할 수 있다. 이 경우

- 오류 메시지를 출력하고 **다시 입력받는다**
- **시도 횟수는 차감하지 않는다** — 오타로 기회를 잃는 것은 부당하기 때문

## 2.3 게임 계속 여부를 묻는 시점

"게임을 계속할 것인지 묻는다"는 요구사항은 **한 판이 완전히 끝난 시점**(정답을 맞췄거나 기회를 모두 소진했을 때)에 묻는 것으로 해석하였다. 매 입력마다 물으면 게임 진행이 번거로워지기 때문이다.

## 2.4 입력 종료(EOF) 처리

사용자가 `Ctrl+D`(Windows는 `Ctrl+Z`)로 입력을 종료하면 오류 없이 정상 종료하도록 하였다.

# 3. 프로그램 구조

## 3.1 함수 구성

프로그램은 기능별로 7개의 함수로 나누었다.

| 함수 | 역할 | 반환값 |
|------|------|--------|
| `main()` | 전체 흐름 제어, 재시작 루프 | 종료 코드 |
| `select_difficulty()` | 난이도 메뉴 출력 및 선택 | 난이도 구조체 포인터 (EOF면 `NULL`) |
| `play_round()` | 한 판 진행 (난수 생성 + 게임 루프) | 1=계속, 0=EOF |
| `print_result()` | 정답·시도 횟수·시도 과정 출력 | 없음 |
| `read_int_in_range()` | 지정 범위의 정수를 받을 때까지 재입력 | 1=성공, 0=EOF |
| `read_line()` | 한 줄 안전하게 읽기 | 1=성공, 0=EOF |
| `parse_int()` | 문자열을 정수로 변환 (검증 포함) | 1=성공, 0=실패 |
| `ask_yes_no()` | y/n 질문 | 1=y, 0=n 또는 EOF |

## 3.2 호출 관계

```
main
 ├─ select_difficulty ─────────┐
 ├─ play_round                 │
 │   └─ print_result           ├─→ read_int_in_range ─┬─ read_line
 │                             │                      └─ parse_int
 └─ ask_yes_no ───────────────────────────────────────── read_line
```

모든 입력이 `read_line()` 하나를 거치므로, 개행 문자 처리·버퍼 초과·입력 종료 감지를 **한 곳에서만** 관리하면 된다.

## 3.3 반환값 규약

프로그램 전체에 일관된 규약을 두었다. **반환값 `0`(포인터의 경우 `NULL`)은 "입력이 끝났으니 프로그램을 종료해야 한다"**는 신호이다. 이 신호가 하위 함수에서 `main()`까지 그대로 전달되어 루프를 빠져나온다.

# 4. 프로그램 동작 과정

## 4.1 난수 생성

```c
srand((unsigned int)time(NULL) ^ ((unsigned int)GET_PID() << 16));
...
const int answer = rand() % (NUMBER_MAX - NUMBER_MIN + 1) + NUMBER_MIN;
```

### (1) `rand()`로 범위 맞추기

`rand()`는 0 이상의 큰 정수를 반환한다. 이를 1~100으로 바꾸는 과정은 다음과 같다.

| 식 | 결과 범위 | 설명 |
|----|-----------|------|
| `rand()` | 0 ~ RAND_MAX | 원래 값 |
| `rand() % 100` | 0 ~ 99 | 100으로 나눈 나머지 |
| `rand() % 100 + 1` | 1 ~ 100 | 1만큼 이동 |

일반화하면 `rand() % (최댓값 - 최솟값 + 1) + 최솟값`이다. 프로그램에서는 `NUMBER_MIN`, `NUMBER_MAX` 매크로를 사용하여, 범위를 1~1000으로 바꾸더라도 이 수식을 고칠 필요가 없게 하였다.

### (2) `srand()`로 씨앗값 설정

`srand()`를 호출하지 않으면 프로그램을 실행할 때마다 **항상 같은 정답**이 나온다. 그래서 현재 시각 `time(NULL)`을 씨앗값으로 사용한다.

그런데 `time()`은 **초 단위**이므로, 프로그램을 1초 안에 두 번 실행하면 씨앗값이 같아져 정답도 같아진다. 실제로 테스트에서 12번 연속 실행했을 때 정답이 모두 `85`로 동일한 문제를 발견하였다. 이를 해결하기 위해 **프로세스 번호(PID)를 섞어** 씨앗값을 만들었다.

| 수정 전 | 12회 연속 실행 결과 |
|---------|---------------------|
| `srand(time(NULL))` | 85, 85, 85, 85, 85, 85, 85, 85, 85, 85, 85, 85 |

| 수정 후 | 12회 연속 실행 결과 |
|---------|---------------------|
| `srand(time(NULL) ^ (getpid() << 16))` | 95, 100, 52, 57, 9, 58, 10, 15, 67, 72, 24, 29 |

또한 `srand()`는 **프로그램 시작 시 딱 한 번만** 호출한다. 매 판마다 호출하면 같은 초에 진행된 판의 정답이 같아지기 때문이다. `rand()`는 한 번 씨앗값이 정해지면 호출할 때마다 다음 값으로 넘어가므로, 판이 바뀌어도 정답은 자연히 달라진다.

## 4.2 반복문

프로그램에는 성격이 다른 세 종류의 반복문이 있다.

### (1) 바깥 루프 — 게임 재시작 (`main`)

```c
for (;;) {
    difficulty = select_difficulty();
    if (difficulty == NULL) break;        /* 입력 종료 */
    if (!play_round(difficulty)) break;   /* 입력 종료 */
    if (!ask_yes_no("...")) break;        /* 사용자가 n 선택 */
}
```

`for(;;)`는 무한 루프이며, 한 번 도는 것이 곧 "한 판"이다. 빠져나가는 경로가 3가지이지만 모두 `break`로 모이므로, 종료 메시지는 루프 바깥에서 한 번만 출력하면 된다.

### (2) 안쪽 루프 — 기회 소진까지 (`play_round`)

```c
while (remaining > 0) {
    ...
    remaining--;
    if (guess == answer) { won = 1; break; }
    ...
}
```

`remaining`(남은 기회)이 0이 되면 자연스럽게 루프가 끝나 패배 처리가 되고, 정답을 맞추면 `break`로 즉시 빠져나온다. 즉 **두 가지 종료 조건**이 한 반복문에 들어 있다.

### (3) 입력 재시도 루프 (`read_int_in_range`)

```c
for (;;) {
    printf("%s", prompt);
    if (!read_line(...)) return 0;
    if (!parse_int(line, &value)) { printf("숫자를 입력해주세요.\n"); continue; }
    if (value < min || value > max)  { printf("...사이로 입력해주세요.\n"); continue; }
    *out = value;
    return 1;     /* 유효한 값을 받았을 때만 여기 도달 */
}
```

`continue`가 곧 "다시 물어보기"이다. 이 함수는 **유효한 값을 받거나, 입력이 끝나거나** 둘 중 하나로만 종료된다. 덕분에 이 함수를 호출하는 쪽(`play_round`)은 유효성 검사를 전혀 신경 쓰지 않아도 된다.

## 4.3 조건문

### (1) 크다/작다 판정

```c
if (guess == answer) {
    won = 1;
    break;
}
printf("%s (남은 기회: %d)\n",
       guess < answer ? "더 큽니다!" : "더 작습니다!", remaining);
```

여기서 주의할 점은 메시지의 **기준**이다. `guess < answer`, 즉 사용자가 입력한 값이 정답보다 작을 때 "더 큽니다"를 출력한다. 정답을 설명하는 것이 아니라 **사용자가 다음에 무엇을 해야 하는지**를 알려주는 것이다.

조건 연산자 `? :`를 사용하면 `if-else`로 `printf`를 두 번 쓰는 것보다 간결하다.

### (2) 시도 과정의 힌트 재구성 (`print_result`)

```c
if (history[i] == answer)      hint = "정답!";
else if (history[i] < answer)  hint = "더 큽니다";
else                           hint = "더 작습니다";
```

시도 과정을 출력할 때는 **숫자만 저장해 두고 힌트는 다시 계산**한다. 힌트 문자열까지 배열에 저장할 필요가 없어 메모리가 절약되고, 힌트 문구를 바꿀 때 한 곳만 고치면 된다.

## 4.4 배열 — 시도 과정 기록

과제 요구사항 ④ "어떤 숫자를 **어떤 과정을 통해** 몇 번의 시도만에 맞췄는지"를 만족하기 위해, 사용자가 입력한 숫자를 배열에 순서대로 저장한다.

```c
#define MAX_ATTEMPTS 15          /* 가장 쉬운 난이도의 기회 수 = 배열 크기 */

int history[MAX_ATTEMPTS];       /* 시도한 숫자를 순서대로 기록 */
int count = 0;                   /* 지금까지의 시도 횟수 */
...
history[count] = guess;
count++;
```

배열 크기를 `MAX_ATTEMPTS`(=15)로 잡은 이유는 **가장 쉬운 난이도의 기회 수가 15번**이어서, 어떤 난이도에서도 시도 횟수가 15를 넘을 수 없기 때문이다. 난이도 정의에서도 같은 매크로를 사용하여 둘이 어긋나지 않도록 하였다.

```c
static const Difficulty DIFFICULTIES[] = {
    { "쉬움",   MAX_ATTEMPTS },   /* ← 배열 크기와 같은 값 */
    { "보통",   10 },
    { "어려움",  5 },
};
```

또한 `count`는 시도 횟수를 세는 역할도 겸한다. 승리했을 때 "몇 번 만에 맞췄는지"는 별도의 변수 없이 `count` 값을 그대로 사용한다.

## 4.5 구조체 — 난이도 정의

```c
typedef struct {
    const char *name;     /* 난이도 이름 */
    int max_attempts;     /* 주어지는 시도 횟수 */
} Difficulty;

static const Difficulty DIFFICULTIES[] = {
    { "쉬움",   MAX_ATTEMPTS },
    { "보통",   10 },
    { "어려움",  5 },
};

#define DIFFICULTY_COUNT ((int)(sizeof DIFFICULTIES / sizeof DIFFICULTIES[0]))
```

난이도의 이름과 시도 횟수는 **항상 짝을 이루는 정보**이므로 구조체로 묶었다. 메뉴 출력도 하드코딩하지 않고 배열을 순회하여 만든다.

```c
for (i = 0; i < DIFFICULTY_COUNT; i++)
    printf("%d) %s - %d번의 기회\n", i + 1, DIFFICULTIES[i].name, DIFFICULTIES[i].max_attempts);
```

이렇게 하면 난이도를 추가할 때 **배열에 한 줄만 추가**하면 메뉴 출력, 입력 범위 검사, 선택 처리가 모두 자동으로 따라온다. `DIFFICULTY_COUNT`는 `sizeof` 연산자로 배열의 원소 개수를 계산하므로 직접 고칠 필요가 없다.

사용자에게 보이는 번호는 1부터지만 배열 인덱스는 0부터이므로, 선택값에서 1을 빼서 사용한다.

```c
return &DIFFICULTIES[choice - 1];
```

## 4.6 입력 처리 — `scanf`를 쓰지 않은 이유

### (1) `scanf`의 무한 루프 문제

숫자 입력에 흔히 쓰는 `scanf("%d", &guess)`에는 문제가 있다. 사용자가 `abc`를 입력하면 `scanf`는 변환에 실패하면서 **입력한 문자를 버퍼에 그대로 남겨 둔다**. 다음 `scanf`가 또 같은 `abc`를 읽고 또 실패하여 **무한 루프**에 빠진다.

이 프로그램은 `fgets()`로 **한 줄을 통째로** 읽는 방식을 사용하여 이 문제를 피하였다.

```c
if (fgets(buf, (int)size, stdin) == NULL)
    return 0;                      /* 입력 종료(EOF) */

len = strlen(buf);
if (len > 0 && buf[len - 1] == '\n') {
    buf[len - 1] = '\0';           /* 개행 문자 제거 */
} else {
    int c;                         /* 버퍼보다 긴 입력 → 남은 문자 버리기 */
    while ((c = getchar()) != '\n' && c != EOF)
        ;
}
```

`fgets`는 개행 문자까지 함께 읽어오므로 마지막 문자를 `'\0'`으로 바꿔 제거한다. 한편 입력이 버퍼 크기(128바이트)보다 길면 개행 문자가 들어오지 않는데, 이때 그냥 넘어가면 남은 글자가 다음 입력으로 밀려 들어온다. `else` 부분의 `while` 루프가 개행 문자까지 모두 읽어 버려 이를 막는다.

### (2) `atoi` 대신 `strtol`

```c
errno = 0;
value = strtol(s, &end, 10);
if (end == s || errno == ERANGE || value < INT_MIN || value > INT_MAX)
    return 0;

while (isspace((unsigned char)*end))
    end++;
if (*end != '\0')
    return 0;      /* 숫자 뒤에 다른 문자가 남아 있으면 실패 */
```

`atoi("12.5")`는 오류 없이 `12`를 반환하지만, `strtol`은 변환이 끝난 위치를 `end` 포인터로 알려준다. 이를 이용해 **문자열 전체가 정확히 하나의 정수일 때만** 통과시킬 수 있다.

| 입력 | 판정 | 이유 |
|------|------|------|
| `42` | 통과 | 전체가 정수 |
| `abc` | 거부 | `end == s` (숫자를 하나도 못 읽음) |
| `12.5` | 거부 | `*end`가 `'.'` (뒤에 문자가 남음) |
| `7 7` | 거부 | `*end`가 `'7'` |
| `99999999999999999999` | 거부 | `errno == ERANGE` (표현 범위 초과) |
| (빈 줄) | 거부 | 공백을 건너뛰면 문자열 끝 |

### (3) `fflush(stdout)`의 필요성

```c
printf("%s", prompt);
fflush(stdout);
```

프롬프트는 개행 문자로 끝나지 않기 때문에, 출력이 버퍼에 머물러 화면에 나타나지 않을 수 있다. 사용자는 아무것도 없는 화면에서 입력을 기다리게 되므로 `fflush()`로 출력을 강제로 내보낸다.

# 5. 전체 소스 코드

## 5.1 guess.c

```c
/*
 * 숫자 맞추기 게임
 *
 * 컴퓨터가 1~100 사이의 난수를 생성하면 사용자가 그 숫자를 맞춘다.
 * 입력할 때마다 정답보다 큰지 작은지 알려주고, 맞추면 한 판이 끝난다.
 * 판이 끝나면 어떤 숫자를 어떤 과정으로 몇 번 만에 맞췄는지 출력한 뒤,
 * 게임을 계속할지 사용자에게 묻는다.
 */

#include <ctype.h>
#include <errno.h>
#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>

#ifdef _WIN32
#  include <windows.h>   /* SetConsoleOutputCP - 콘솔 한글 출력 */
#  include <process.h>   /* _getpid */
#  define GET_PID() _getpid()
#else
#  include <unistd.h>    /* getpid */
#  define GET_PID() getpid()
#endif

#define LINE_BUF_SIZE 128
#define NUMBER_MIN 1
#define NUMBER_MAX 100
#define MAX_ATTEMPTS 15  /* 가장 쉬운 난이도의 기회 수 = 시도 이력 배열의 크기 */

typedef struct {
    const char *name;
    int max_attempts;
} Difficulty;

static const Difficulty DIFFICULTIES[] = {
    { "쉬움",   MAX_ATTEMPTS },
    { "보통",   10 },
    { "어려움",  5 },
};

#define DIFFICULTY_COUNT ((int)(sizeof DIFFICULTIES / sizeof DIFFICULTIES[0]))

/* 한 줄을 읽어 개행을 제거한다. EOF면 0, 성공하면 1을 반환한다. */
static int read_line(char *buf, size_t size)
{
    size_t len;

    if (fgets(buf, (int)size, stdin) == NULL)
        return 0;

    len = strlen(buf);
    if (len > 0 && buf[len - 1] == '\n') {
        buf[len - 1] = '\0';
    } else {
        /* 버퍼보다 긴 입력이 들어온 경우 남은 문자를 버린다. */
        int c;
        while ((c = getchar()) != '\n' && c != EOF)
            ;
    }
    return 1;
}

/* 문자열 전체가 하나의 정수일 때만 파싱에 성공한다. */
static int parse_int(const char *s, int *out)
{
    char *end;
    long value;

    while (isspace((unsigned char)*s))
        s++;
    if (*s == '\0')
        return 0;

    errno = 0;
    value = strtol(s, &end, 10);
    if (end == s || errno == ERANGE || value < INT_MIN || value > INT_MAX)
        return 0;

    while (isspace((unsigned char)*end))
        end++;
    if (*end != '\0')
        return 0;

    *out = (int)value;
    return 1;
}

/* min~max 범위의 정수를 받을 때까지 되묻는다. EOF면 0을 반환한다. */
static int read_int_in_range(const char *prompt, int min, int max, int *out)
{
    char line[LINE_BUF_SIZE];
    int value;

    for (;;) {
        printf("%s", prompt);
        fflush(stdout);

        if (!read_line(line, sizeof line))
            return 0;

        if (!parse_int(line, &value)) {
            printf("숫자를 입력해주세요.\n");
            continue;
        }
        if (value < min || value > max) {
            printf("%d~%d 사이로 입력해주세요.\n", min, max);
            continue;
        }

        *out = value;
        return 1;
    }
}

/* y면 1, n이면 0. EOF도 0(종료)으로 취급한다. */
static int ask_yes_no(const char *prompt)
{
    char line[LINE_BUF_SIZE];
    const char *p;

    for (;;) {
        printf("%s", prompt);
        fflush(stdout);

        if (!read_line(line, sizeof line))
            return 0;

        for (p = line; isspace((unsigned char)*p); p++)
            ;

        if (*p == 'y' || *p == 'Y')
            return 1;
        if (*p == 'n' || *p == 'N')
            return 0;

        printf("y 또는 n을 입력해주세요.\n");
    }
}

/* 난이도를 고른다. EOF면 NULL을 반환한다. */
static const Difficulty *select_difficulty(void)
{
    int i, choice;

    printf("\n=== 난이도 선택 ===\n");
    for (i = 0; i < DIFFICULTY_COUNT; i++)
        printf("%d) %s - %d번의 기회\n", i + 1, DIFFICULTIES[i].name, DIFFICULTIES[i].max_attempts);

    if (!read_int_in_range("선택 (1-3): ", 1, DIFFICULTY_COUNT, &choice))
        return NULL;

    return &DIFFICULTIES[choice - 1];
}

/* 한 판이 끝난 뒤 정답, 시도 횟수, 시도 과정을 한꺼번에 보여준다. */
static void print_result(const Difficulty *difficulty, int answer,
                         const int *history, int count, int won)
{
    int i;

    printf("\n========= 게임 결과 =========\n");
    printf("난이도   : %s (%d번의 기회)\n", difficulty->name, difficulty->max_attempts);
    printf("정답     : %d\n", answer);
    if (won)
        printf("결과     : 성공! %d번 만에 맞췄습니다.\n", count);
    else
        printf("결과     : 실패 (%d번의 기회를 모두 사용)\n", count);

    printf("진행 과정 :\n");
    for (i = 0; i < count; i++) {
        const char *hint;

        if (history[i] == answer)
            hint = "정답!";
        else if (history[i] < answer)
            hint = "더 큽니다";
        else
            hint = "더 작습니다";

        printf("  %2d번째 시도: %3d  ->  %s\n", i + 1, history[i], hint);
    }
    printf("=============================\n");
}

/* 한 판을 진행한다. 도중에 EOF를 만나면 0을 반환한다. */
static int play_round(const Difficulty *difficulty)
{
    const int answer = rand() % (NUMBER_MAX - NUMBER_MIN + 1) + NUMBER_MIN;
    int history[MAX_ATTEMPTS];   /* 사용자가 시도한 숫자를 순서대로 기록 */
    int count = 0;               /* 지금까지의 시도 횟수 */
    int remaining = difficulty->max_attempts;
    int won = 0;
    int guess;
    char prompt[64];

    snprintf(prompt, sizeof prompt, "숫자를 입력하세요 (%d-%d): ", NUMBER_MIN, NUMBER_MAX);

    printf("\n[%s] %d~%d 사이의 숫자를 %d번 안에 맞춰보세요!\n",
           difficulty->name, NUMBER_MIN, NUMBER_MAX, difficulty->max_attempts);

    while (remaining > 0) {
        if (!read_int_in_range(prompt, NUMBER_MIN, NUMBER_MAX, &guess))
            return 0;

        history[count] = guess;   /* 시도 과정 기록 */
        count++;
        remaining--;

        if (guess == answer) {
            won = 1;
            break;
        }

        printf("%s (남은 기회: %d)\n",
               guess < answer ? "더 큽니다!" : "더 작습니다!", remaining);
    }

    print_result(difficulty, answer, history, count, won);
    return 1;
}

int main(void)
{
#ifdef _WIN32
    SetConsoleOutputCP(CP_UTF8);   /* Windows 콘솔에서 한글이 깨지지 않도록 */
#endif

    /* time() 은 초 단위라 연속 실행 시 시드가 겹친다. PID 를 섞어 판을 구분한다. */
    srand((unsigned int)time(NULL) ^ ((unsigned int)GET_PID() << 16));

    printf("=== 숫자 맞추기 게임 ===\n");

    for (;;) {
        const Difficulty *difficulty = select_difficulty();
        if (difficulty == NULL)
            break;

        if (!play_round(difficulty))
            break;

        if (!ask_yes_no("\n새 게임을 시작하시겠습니까? (y/n): "))
            break;
    }

    printf("\n게임을 종료합니다. 안녕히 가세요!\n");
    return 0;
}
```

# 7. 사용 도구

과제 안내에 따라, 비주얼 스튜디오를 사용하지 않았으므로 사용한 도구를 설명한다.

| 항목 | 내용 |
|------|------|
| 운영체제 | macOS (Darwin 25.6.0) |
| 편집기 | 터미널 기반 편집 환경 |
| 컴파일러 | Apple clang (Xcode Command Line Tools) |
| 빌드 도구 | GNU Make |
| Windows 실행 파일 | mingw-w64 크로스 컴파일러 (x86_64-w64-mingw32-gcc) |

## 7.1 macOS 실행 파일 빌드

macOS에는 비주얼 스튜디오가 없으므로, Xcode Command Line Tools에 포함된 `clang` 컴파일러를 사용하였다.

```
$ cc -Wall -Wextra -O2 -o guess guess.c
$ ./guess
```

`-Wall -Wextra`는 경고를 최대한 표시하는 옵션이며, 최종 소스는 **경고 없이** 컴파일된다.

## 7.2 Windows 실행 파일(.exe) 빌드

제출물에 `.exe` 파일이 필요하나 macOS에서는 직접 만들 수 없으므로, **mingw-w64 크로스 컴파일러**를 사용하였다. 크로스 컴파일이란 한 운영체제에서 다른 운영체제용 실행 파일을 만드는 것을 말한다.

```
$ x86_64-w64-mingw32-gcc -Wall -Wextra -O2 -static -o guess.exe guess.c
```

`-static` 옵션으로 정적 링크하여, 별도의 DLL 파일 없이 `guess.exe` 하나만으로 실행되도록 하였다.

## 7.3 Windows 호환을 위한 조건부 컴파일

같은 소스 파일이 macOS와 Windows 양쪽에서 컴파일되도록 전처리기 조건문을 사용하였다.

```c
#ifdef _WIN32
#  include <windows.h>   /* SetConsoleOutputCP - 콘솔 한글 출력 */
#  include <process.h>   /* _getpid */
#  define GET_PID() _getpid()
#else
#  include <unistd.h>    /* getpid */
#  define GET_PID() getpid()
#endif
```

`_WIN32`은 Windows용으로 컴파일할 때 자동으로 정의되는 매크로이다. 두 가지를 처리하였다.

1. **프로세스 번호 함수 이름이 다르다** — Windows는 `_getpid()`, 그 외는 `getpid()`이므로 `GET_PID()` 매크로로 통일하였다.
2. **한글 출력** — Windows 명령 프롬프트의 기본 문자 인코딩은 UTF-8이 아니어서 한글이 깨질 수 있다. 프로그램 시작 시 `SetConsoleOutputCP(CP_UTF8)`을 호출하여 콘솔을 UTF-8로 전환하였다.

```c
int main(void)
{
#ifdef _WIN32
    SetConsoleOutputCP(CP_UTF8);   /* Windows 콘솔에서 한글이 깨지지 않도록 */
#endif
```

# 8. 테스트 및 검증

정답이 매번 달라지는 프로그램이므로, 화면 출력을 읽고 이분 탐색으로 자동 응답하는 **테스트 프로그램**을 따로 작성하여 검증하였다. 검증한 항목은 다음과 같다.

| 구분 | 검증 내용 | 결과 |
|------|-----------|------|
| 승리 흐름 | 이분 탐색으로 정답 도달, 시도 횟수 정확 | 통과 |
| 패배 흐름 | 기회 5→0 감소, 정답 공개 | 통과 |
| 시도 과정 | 기록된 이력이 실제 입력한 숫자·순서와 일치 | 통과 |
| 시도 과정 | 각 이력의 힌트 방향(더 큽니다/작습니다)이 정확 | 통과 |
| 잘못된 입력 | `abc`, 빈 줄, `0`, `101`, `12.5`, `7 7`, `-5`, 공백 → 모두 거부, **기회 차감 없음** | 통과 |
| 재시작 | `y` → 난이도 선택부터 다시, `n` → 종료 | 통과 |
| y/n 질문 | `maybe` 등 잘못된 답 → 재질문, 대문자 `N` 인식 | 통과 |
| 입력 종료 | 난이도 선택 중 / 게임 중 / 오입력 후 EOF → 모두 정상 종료 | 통과 |

## 8.1 테스트 중 발견하여 수정한 문제

**문제**: 프로그램을 연속으로 12번 실행했더니 정답이 모두 `85`로 같았다.

## 9.1 과제 요구사항 충족 여부

| 요구사항 | 충족 |
|----------|------|
| 1~100 사이의 난수 생성 | 충족 — `rand() % 100 + 1` |
| 입력할 때마다 크거나 작음 안내 | 충족 — `if-else` 및 조건 연산자 |
| 숫자를 맞추면 게임 종료 | 충족 — `break` |
| 어떤 숫자를, 어떤 과정으로, 몇 번 만에 맞췄는지 출력 | 충족 — 배열 `history[]`와 `print_result()` |
| 게임 계속 여부를 묻고 진행 결정 | 충족 — `ask_yes_no()`와 무한 루프 |

## 9.2 배운 점

- **난수의 씨앗값**: `srand()`는 프로그램당 한 번만 호출해야 하며, `time()`만으로는 연속 실행 시 값이 겹칠 수 있다는 것을 실제 테스트로 확인하였다.
- **입력 처리의 중요성**: `scanf`의 버퍼 문제는 교재의 예제처럼 올바른 입력만 들어올 때는 드러나지 않지만, 실제 사용자는 언제든 잘못된 입력을 할 수 있다. `fgets`와 `strtol`을 조합하면 이를 안전하게 처리할 수 있다.
- **함수 분리의 효과**: 입력 검증을 `read_int_in_range()` 안에 가두었더니, 게임 로직을 담당하는 `play_round()`는 규칙에만 집중할 수 있었다. 잘못된 입력이 시도 횟수를 차감하지 않는 동작도 이 구조 덕분에 자연스럽게 구현되었다.
- **배열의 활용**: 단순히 시도 횟수만 세는 것이 아니라 입력값 자체를 배열에 보관하니, 게임이 끝난 뒤 전체 과정을 되돌아보여 줄 수 있었다.
